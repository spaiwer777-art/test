# Протокол «Щит» — онлайн-версия

Сайт работает на хостинге в интернете. Игроки подключаются с любых телефонов
и из любой сети (мобильный интернет, любой Wi-Fi), находиться в одной сети не нужно.

Есть два способа разместить сайт, выберите тот, что подходит вашему хостингу.

---

## Способ 1. Обычный хостинг с PHP (Beget, Timeweb, REG.RU и т.п.)

Подходит для большинства недорогих хостингов: Apache и PHP 7 или новее.

1. Откройте файл `public/backend/key.php` в Блокноте и замените `ПОМЕНЯЙТЕ-МЕНЯ`
   на свой ключ ведущего, например `shield-6b-2026-tigr`. **Пока ключ не заменён,
   вход ведущего не работает**: так ключ по умолчанию не сможет подобрать никто.
2. Загрузите **содержимое папки `public`** в папку сайта на хостинге
   (обычно `public_html` или `www`). Скрытый файл `.htaccess` тоже нужно загрузить,
   без него игра работать не будет.
3. Проверьте, что в папку `backend/data` можно записывать: там хранится состояние игры.
   Обычно это так по умолчанию; если нет, выставьте права 755 или 775 в файловом
   менеджере хостинга.
4. Включите HTTPS (бесплатный сертификат Let's Encrypt есть почти у всех хостингов).
   Без HTTPS на телефонах может не работать удержание экрана во время таймера.

Если хостинг на чистом nginx (без Apache), `.htaccess` не сработает. Тогда используйте способ 2.

## Способ 2. Хостинг с Node.js (Render, Railway, VPS, Docker)

1. Загрузите всю папку проекта (с `server.js` и папкой `public`), например через GitHub.
2. Команда запуска: `node server.js`. Устанавливать ничего не нужно, внешних зависимостей нет.
3. Задайте переменную окружения `HOST_KEY` — это ключ ведущего.
   Если её не задать, сервер придумает ключ сам и напечатает его в логах.
4. Порт сервер берёт из переменной `PORT`, которую хостинг задаёт сам.

Для Render.com в проекте есть `render.yaml`, для Docker — `Dockerfile`:

    docker build -t shield .
    docker run -e HOST_KEY=ваш-ключ -p 8080:8080 shield

## Как проходит игра

- **Ведущий** открывает сайт → «Терминал защиты» → вводит ключ ведущего.
  Ключ запоминается в этом браузере на неделю, дальше терминал, «Конструктор игры» и
  «QR-коды» открываются сразу. Выйти можно на стартовой странице
  (это важно, если компьютер общий).
  Можно сразу открыть ссылку `https://ваш-сайт/index.html?host=ваш-ключ`:
  ключ запомнится и пропадёт из адресной строки.
- **Игроки и капитан** сканируют QR-коды с экрана терминала, ключ им не нужен.
  QR-коды автоматически ведут на адрес вашего сайта.
- **Задания на фигурках** открываются по QR-наклейкам (`/q/<код>/`). Наклейки печатаются
  на странице «QR-коды». Если сменили домен, перепечатайте их.

## Безопасность (почему так)

В локальной версии «компьютер штаба» определялся по IP. В интернете так нельзя:
адрес и сеть ничего не доказывают. Поэтому права ведущего даёт секретный ключ,
и проверяет его **сервер**, а не страница:

- без ключа `js/config.js` приходит **без ответов** (только настройки таймера);
- команды ведущего (сброс игры, смена капитана, открытие Матрицы, конструктор,
  коды QR) без ключа получают отказ 403;
- папка `zadaniya` закрыта: задание открывается только по коду с наклейки;
- состояние игры (`backend/data`), ключ (`key.php`), `server.js` и `setup.json`
  из браузера не скачиваются.

## Если что-то не работает

- **Терминал пишет «Сервер игры не отвечает»**: сайт залит как простая статика.
  Нужен PHP с `.htaccess` (способ 1) или Node (способ 2). GitHub Pages и Netlify без
  функций не подойдут.
- **«Ключ не подошёл»**: проверьте `key.php` или `HOST_KEY`. После правки `key.php`
  хостингу может понадобиться несколько секунд, чтобы его перечитать.
- **«На сервере ещё не задан ключ ведущего»**: в `key.php` осталось `ПОМЕНЯЙТЕ-МЕНЯ`.
- **Ошибка записи `backend/data/state.json`**: дайте папке `backend/data` права на запись.
